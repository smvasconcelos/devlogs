## Por que Dockerizar o seu Frontend?

1. **Consistência Total:** A mesma versão do Node.js e Package Manager (yarn, npm, pnpm, etc) para todos.
2. **Setup Zero:** Esqueça o "npm install" demorado no host; o container resolve tudo.
3. **Isolamento:** Evite conflitos de bibliotecas globais na sua máquina.
4. **Dev Containers:** Sincronize extensões como ESLint e Prettier diretamente pelo container.

##  Dockerfile (O Coração do Ambiente)

Utilizamos a imagem `node:24-alpine` para manter o ambiente leve e seguro. Observe que configuramos o usuário `node` para evitar problemas de permissão de arquivos no Linux/Mac.

```dockerfile
# Dockerfile

FROM node:24-alpine

RUN apk add --no-cache libc6-compat git

WORKDIR /app

RUN chown -R node:node /app

USER node

COPY --chown=node:node package*.json yarn.lock ./
COPY --chown=node:node tsconfig*.json ./

RUN yarn install

COPY --chown=node:node . .

EXPOSE 5173

CMD ["yarn", "dev"]
```
## Docker Compose (Orquestração)

O Compose gerencia o mapeamento das portas e os volumes. O volume `/app/node_modules` é essencial para que o Docker não tente usar os módulos instalados na sua máquina host (caso existam).

```yaml

# docker-compose.yml

services:
  app:
    build: .
    image: react-docker:dev
    container_name: react-docker
    ports:
      - 5173:5173
    volumes:
      - .:/app
      - /app/node_modules
```

## Arquivo .dockerignore

Não queremos enviar lixo para dentro da imagem. Este arquivo garante um build rápido.

```text
# .dockerignore

node_modules
dist
.git
.devcontainer
```

## Dev Containers (A Mágica do VS Code)

O arquivo `.devcontainer/devcontainer.json` garante que, ao abrir o projeto, o VS Code já sugira e instale as extensões de linting e formatação.

```JSON
// devcontainer.json

{
  "name": "React Docker",
  "dockerComposeFile": "../docker-compose.yml",
  "service": "app",
  "workspaceFolder": "/app",
  "remoteUser": "node",
  "customizations": {
    "vscode": {
      "settings": {
        "editor.defaultFormatter": "esbenp.prettier-vscode",
        "editor.formatOnSave": true,
        "editor.codeActionsOnSave": {
          "source.fixAll.eslint": "explicit"
        }
      },
      "extensions": [
        "esbenp.prettier-vscode",
        "dbaeumer.vscode-eslint",
        "styled-components.vscode-styled-components"
      ]
    }
  }
}
```
##  Ajuste no Vite (Atenção aqui!)

Para que o Vite aceite conexões vindas do Docker (rede externa ao localhost do container), altere seu script no `package.json`:

```JSON
// package.json (scripts)

{
	...
	"scripts": {
		"dev": "vite --host 0.0.0.0",
		...
	}
}
```

## Como Executar

1. Abra a pasta do projeto no VS Code.
2. Com a extensão **Dev Containers** instalada, clique em "Reopen in Container".
	1. Se preferir pode subir o container separadamente com `docker-compose up --build` 
	2. E após no script do vscode `ctrl + shift + p` e digitar `Dev Containers: Reopen in COntainer`
3. Aguarde o build e pronto! Seu ambiente está configurado e com as ferramentas de qualidade de código ativas.
