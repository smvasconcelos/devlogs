Docker #01 - How to dockerize a react app

As a fullstack developer, I know that setting up a development environment can be one of the most repetitive tasks in a project. The goal of this guide is to create a standardized environment where any developer can run the project in seconds, with all VS Code extensions pre-configured.

Why Dockerize Your Frontend?⌗

  1. Total Consistency: The same version of Node.js and Package Manager (yarn, npm, pnpm, etc.) for everyone.
  2. Zero Setup: Forget time-consuming “npm install” on the host machine; the container handles everything.
  3. Isolation: Avoid global library conflicts on your machine.
  4. Dev Containers: Sync extensions like ESLint and Prettier directly through the container.

Dockerfile (The Heart of the Environment)⌗

We use the node:24-alpine image to keep the environment lightweight and secure. Note that we configure the node user to avoid file permission issues on Linux/Mac.

# Dockerfile

FROM node:24-alpine

RUN apk add --no-cache libc6-compat git

WORKDIR /app

RUN chown -R node:node /app

USER node

COPY --chown=node:node package*.json yarn.lock ./
COPY --chown=node:node tsconfig*.json ./

RUN yarn install

COPY --chown=node:node . .

EXPOSE 5173

CMD ["yarn", "dev"]

Docker Compose (Orchestration)⌗

Compose manages port mapping and volumes. The /app/node_modules volume is essential so that Docker doesn’t attempt to use modules installed on your host machine (if they exist).

# docker-compose.yml

services:
  app:
    build: .
    image: react-docker:dev
    container_name: react-docker
    ports:
      - 5173:5173
    volumes:
      - .:/app
      - /app/node_modules

.dockerignore File⌗

We don’t want to send unnecessary files into the image. This file ensures a fast build.

# .dockerignore

node_modules
dist
.git
.devcontainer

Dev Containers (The VS Code Magic)⌗

The .devcontainer/devcontainer.json file ensures that when the project is opened, VS Code automatically suggests and installs linting and formatting extensions.

// devcontainer.json

{
  "name": "React Docker",
  "dockerComposeFile": "../docker-compose.yml",
  "service": "app",
  "workspaceFolder": "/app",
  "remoteUser": "node",
  "customizations": {
    "vscode": {
      "settings": {
        "editor.defaultFormatter": "esbenp.prettier-vscode",
        "editor.formatOnSave": true,
        "editor.codeActionsOnSave": {
          "source.fixAll.eslint": "explicit"
        }
      },
      "extensions": [
        "esbenp.prettier-vscode",
        "dbaeumer.vscode-eslint",
        "styled-components.vscode-styled-components"
      ]
    }
  }
}

Vite Adjustment (Pay attention here!)⌗

For Vite to accept connections coming from Docker (external network relative to the container’s localhost), update your script in package.json:

// package.json (scripts)

{
    ...
    "scripts": {
        "dev": "vite --host 0.0.0.0",
        ...
    }
}

How to Run⌗

  1. Open the project folder in VS Code.
  2. With the Dev Containers extension installed, click “Reopen in Container”.
  3. Alternatively, you can start the container separately with docker-compose up --build.
  4. Then, use the VS Code command palette (Ctrl + Shift + P) and type Dev Containers: Reopen in Container.
  5. Wait for the build, and you’re done! Your environment is configured with code quality tools active.
